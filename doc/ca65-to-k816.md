# From ca65 to K816

This is the reference for carrying a program written for ca65 over to
K816, with the program linking and running at every step. It has four
parts: the idiom table, which says what K816 writes where ca65 writes each
thing; the converter, which writes that table out for a whole program;
the loop, which is how a file is converted by hand and checked; and the
list of what K816 does not have, so that a missing thing is recognized as
missing rather than searched for.

Every pair of listings below that carries a name — a `ca65 NAME` block
followed by a `k65 NAME` block — is assembled by `tests/ca65_guide.rs`,
both sides, and linked to the same bytes. A spelling in this document is
one that has been checked, not one that was remembered. The `K816-CA65-`
diagnostics the compiler reports when it meets a ca65 idiom point here.

## The idiom table

### Comments and separators

ca65 comments run from `;` to the end of the line. K816's comments are
`//` and `/* … */`; its `;` is a statement **separator**, so a ca65
comment left in a K816 file is read as a separator followed by code. One
whose words did not parse is `K816-CA65-0001`; one whose words did — `;
load one` is two calls — is the same code as a warning, and then two
undeclared names.

```text
    lda #1 ; load one        ca65
    lda #1 // load one       K816
```

### Sections and labels

ca65 places code wherever a label is; K816 code lives in a named section
whose name is the label. `.proc NAME … .endproc` and a bare `NAME:` with
code after it are both `func NAME { … }`. The `rts` is implied — K816
adds one at the end of every `func` — and `naked NAME` is the section
that must not have it: a tail jump, an interrupt handler ending in `rti`.

```ca65 sections
.setcpu "65816"
.export start
.code
.a8
.i8
start:
    lda #$42
    sta $0200
    rts
.proc helper
    inc $0200
    rts
.endproc
```

```k65 sections
func start @a8 @i8 {
    lda #$42
    sta $0200
}
func helper @a8 @i8 {
    inc $0200
}
```

A cheap local `@loop` is `.loop`, scoped to its section exactly as the
cheap local was to its `.proc`. ca65's unnamed labels (`:` with `:+` and
`:-`) have no counterpart; name them.

```ca65 locals
.setcpu "65816"
.code
.a8
.i8
start:
    ldx #4
@loop:
    dex
    bne @loop
    rts
```

```k65 locals
func start @a8 @i8 {
    ldx #4
.loop:
    dex
    bne .loop
}
```

### Segments

| ca65                 | K816                                              |
| -------------------- | ------------------------------------------------- |
| `.segment "NAME"`    | `segment NAME` — unquoted                         |
| `.code`              | `segment CODE`                                    |
| `.rodata`            | `segment RODATA`                                  |
| `.data`              | `segment DATA`                                    |
| `.bss`               | `segment BSS`                                     |
| `.zeropage` + `.res` | `var dp NAME`, in any segment; see below          |
| `.org $ADDR`         | the address on the declaration: `var X = $ADDR`   |
| `.reloc`             | nothing                                           |

A `segment` directive is in force until the next one, as in ca65. Inside
a `data` block it is scope-local and must be the block's first entry.

### Register widths

This is the one place K816 is more than a respelling. ca65's
`.a8`/`.a16`/`.i8`/`.i16` are assertions it uses to size immediates and
checks against nothing; a `sep`/`rep` is yours to keep consistent with
them. In K816 a width is a **contract**: a function declares the widths
it runs at, every call to it is bridged with the `sep`/`rep` that
satisfies the contract, a `@a16 { … }` block widens for its extent and
restores after it, and a width-dependent immediate under an unknown width
is an error rather than a guess.

```ca65 widths
.setcpu "65816"
.code
.a8
.i8
start:
    rep #$20
    .a16
    lda #$1234
    sta $0200
    sep #$20
    .a8
    lda #$12
    rts
```

```k65 widths
func start @a8 @i8 {
    @a16 {
        lda #$1234
        sta $0200
    }
    lda #$12
}
```

| ca65                          | K816                                             |
| ----------------------------- | ------------------------------------------------ |
| `.a8` / `.a16` / `.i8` / `.i16` as a statement | `@a8` … as a statement: the width from here on |
| the same, at a routine's head | `func NAME @a16 @i16 { … }`: the contract         |
| `rep #$20` … `sep #$20`       | `@a16 { … }`: the block emits both and restores  |
| `.smart`                      | nothing: every `sep`/`rep` is tracked, always    |
| a routine's exit width        | inferred from its returns; `-> @a16` to assert it |

Three consequences to expect. **A routine the ca65 source calls at two
different widths** gets one contract, and K816 bridges the call that
disagrees; `tools/ca65-widths.py` lists those calls before you start.
**`main` and an interrupt handler** take their widths from the entry ABI
(`--entry`, default `native,a8,i8`) rather than from an annotation, and
an annotation on them is a claim K816 checks. **A hand-written `sep` or
`rep` the width model can prove redundant is deleted** by the optimizer,
which `k816 emit-ir --after-opt --explain` will show; the bytes are
different and the program is not.

### Data

A ca65 data label with directives after it is a `data NAME { … }`
block. Values are bare bytes, or typed entries; a string is a string
followed by its terminator, since `.asciiz` has no counterpart.

```ca65 data
.setcpu "65816"
.rodata
table:
    .byte 1, 2, $7F
    .asciiz "HI"
    .word $1234, table
    .faraddr table
.data
counter: .res 2
```

```k65 data
segment RODATA
data table {
    1 2 $7F
    "HI" 0
    word $1234 table
    far table
}
segment DATA
var counter:word
```

A typed entry — `word`, `far` — takes **every value after it** up to the
next keyword, label or directive, a line break included, so a string or a
bare number written after `far table` is three bytes wide. Put the bytes
and strings first, begin a new `byte` entry, or label them:

```k65
data state {
    task: word 0
    lock: word 0
    name: "shell" 0
}
```

This is the trap in a device table: `word handler` on one line and `'K'`
on the next makes the letter a word, and the table's three-byte entries
go out of step. Write `byte 'K'`.

| ca65                    | K816                                              |
| ----------------------- | ------------------------------------------------- |
| `.byte A, B`            | `A B`, or `byte A B` when a value is a name       |
| `.word A` / `.addr A`   | `word A`                                          |
| `.faraddr A`            | `far A`                                           |
| `.dword A`              | two `word` entries, low word first                |
| `.dbyt A`               | `byte &>A &<A`                                    |
| `.asciiz "s"`           | `"s" 0`                                           |
| `.res N` (storage)      | `var NAME[N]` for N bytes, `var NAME:word` for 2  |
| `.res N` (in a block)   | `?` entries, one per byte                         |
| `.align N`              | `align N`, first in the block                     |
| `.repeat N` … `.endrep` | `repeat N { … }`                                  |
| `'A'`                   | `'A'`                                             |
| `.feature string_escapes` | `\n \r \t \0 \\ \"` are always on; `\xNN` is not: write the byte as a value |

The `K816-CA65-0002` diagnostic names each directive and its spelling.

```ca65 repeat
.setcpu "65816"
.rodata
.align 4
pattern:
.repeat 3
    .byte $AA, $55
.endrepeat
```

```k65 repeat
segment RODATA
data pattern {
    align 4
    repeat 3 { $AA $55 }
}
```

### Variables and the zero page

ca65 reserves storage with a label and `.res`; K816 declares it with
`var`. A `var` with no address is placed by ld65 in the current segment;
`var dp` goes to the direct page, which K816 reserves in a `ZEROPAGE`
segment of its own and references in one byte, exported as `.exportzp`.

```ca65 zeropage
.setcpu "65816"
.zeropage
ptr: .res 2
.code
.a8
.i8
start:
    lda (ptr),y
    sta ptr
    rts
```

```k65 zeropage
var dp ptr[2]
func start @a8 @i8 {
    lda (ptr),y
    sta ptr
}
```

A width suffix — `var counter:word` — is a claim K816 checks every
access against (`K816-E0140`), so `ptr` above is declared as a two-byte
span rather than a `:word`: it is stored to a byte at a time under `@a8`.
Declare a width where the datum has one, and leave it off where a routine
reads the thing in pieces.

A label under `.org` is a pinned `var`, and its address is a number K816
knows: another pinned `var` may be declared over it, in the unit that
declares it or in one that imports it. An allocated `var`'s address is
ld65's, and an initializer that reads one is `K816-E0108`.

```k65
var text_buffer = $4000
var chargen = text_buffer + $0800
```

### Constants and enumerations

```ca65 constants
.setcpu "65816"
.enum
    TASK_FREE
    TASK_RUNNING
    TASK_STOPPED
.endenum
.define LIMIT 32
MASK = %00110000
.code
.a8
.i8
start:
    lda #TASK_STOPPED
    ldx #LIMIT
    ldy #MASK
    rts
```

```k65 constants
const TASK_FREE = 0, TASK_RUNNING, TASK_STOPPED
const LIMIT = 32
const MASK  = %00110000
func start @a8 @i8 {
    lda #TASK_STOPPED
    ldx #LIMIT
    ldy #MASK
}
```

A `const` names a value and is not an address: `lda K` is refused where
ca65 would read memory at `K`, and `lda #K` is what was meant. The
compile-time evaluator, `[ … ]`, is the other way to define one and the
way to compute a table.

### Structures and field access

A `.struct` with an `.org` is a field layout at a fixed address; one
without is an `abstract var`, which has offsets and a size and no
address. `NAME::field` is `NAME.field`; `.sizeof(NAME)` is
`NAME:sizeof`; a field's offset is `NAME.field:offsetof`.

```ca65 structs
.setcpu "65816"
.struct REGS
    .org $FF80
    in0  .byte
    out0 .byte
    pair .word
.endstruct
.struct REC
    tag   .byte
    count .word
.endstruct
.code
.a8
.i8
start:
    lda REGS::in0
    sta REGS::out0
    lda #.sizeof(REC)
    ldx #REC::count
    rts
```

```k65 structs
var REGS[
    .in0  :byte
    .out0 :byte
    .pair :word
] = $FF80
abstract var REC[
    .tag   :byte
    .count :word
]
func start @a8 @i8 {
    lda REGS.in0
    sta REGS.out0
    lda #REC:sizeof
    ldx #REC.count:offsetof
}
```

A `.tag` — storage shaped like a struct — is a `var` that repeats the
fields, and a table of them is `var NAME[ … ] * COUNT`, indexed
`NAME[i].field` at compile time or `NAME.field,x` at run time.

**A field has the width it was declared with.** ca65 moves as many bytes
as the register is wide, so `lda IO::status` under `.a16` reads the status
byte and the one after it; K816 holds `IO.status` to its `:byte` and calls
that `K816-E0140`. A use-site view says the two bytes were meant:

```ca65 view
.setcpu "65816"
.struct IO
    .org $D000
    status .byte
    data   .byte
.endstruct
.code
.a16
poll:
    lda IO::status
    and #$00FF
    rts
```

```k65 view
var IO[
    .status :byte
    .data   :byte
] = $D000
func poll @a16 {
    lda IO.status:word
    and #$00FF
}
```

**A hardware include is a unit of its own.** Its `.struct` at an `.org`
becomes a `var` layout, and every unit that imports the include reads
`RIA.op` — and `TASKS.state,x`, `&&TASKS[1]`, `TASKS:sizeof` — exactly
as the declaring unit does: a layout crosses a direct `import` with its
variable, an `abstract var`'s and a `var`'s alike (`syntax-reference.md`,
"Abstract symbolic layouts").

```k65
var RIA[
    .uart_rdy  :byte
    .uart_rxtx :byte
] = $FFE0
```

`k816 bind --layouts` writes that form from a linked program's debug
file, and `--flat` one exported equate per register instead, which is
how the original K65 sources write theirs.

### Address bytes

| ca65                 | K816                       |
| -------------------- | -------------------------- |
| `#<X` / `.lobyte(X)` | `#&<X`                     |
| `#>X` / `.hibyte(X)` | `#&>X`                     |
| `#^X` / `.bankbyte(X)` | `#X >> 16`: no operator  |
| `.loword(X)`         | `#&&X`, a 16-bit immediate |
| `.byte <X, >X`       | `&<X &>X`                  |

```ca65 addrbytes
.setcpu "65816"
.code
.a8
.i8
start:
    lda #<target
    ldx #>target
    rts
target:
    .byte $EA
```

```k65 addrbytes
func start @a8 @i8 {
    lda #&<target
    ldx #&>target
}
data target { $EA }
```

### Instructions

Every legal 65816 instruction is written as in ca65, with these
differences of spelling:

| ca65                     | K816                                         |
| ------------------------ | -------------------------------------------- |
| `pea $1234`              | `pea #$1234`: the operand is a value          |
| `cop $05`, `cop #$05`    | `cop #$05`                                    |
| `brk` (one byte)         | `brk #0`: the signature byte is always written |
| `mvn #$01, #$02`         | `mvn 1,2`                                     |
| `lda f:X` / `a:X` / `z:X`| `lda far X` / `lda abs X` / `lda dp X`        |
| `jmp *`                  | a local label: `.here: jmp .here`             |
| `add`/`sub` (`.macpack generic`) | `clc` `adc` / `sec` `sbc`             |
| `.p816`, `.setcpu`       | nothing: the CPU is the 65816                 |

```ca65 instructions
.setcpu "65816"
.code
.a8
.i8
start:
    pea $1234
    pei ($12)
    cop #$05
    brk $00
    mvn #$01, #$02
    lda f:$123456
    lda a:$0012
    lda z:$12
    rts
```

```k65 instructions
func start @a8 @i8 {
    pea #$1234
    pei ($12)
    cop #$05
    brk #0
    mvn 1,2
    lda far $123456
    lda abs $0012
    lda dp $12
}
```

A `far func` is one entered by `JSL` and ending in `RTL`; `jsl` and
`call far` both reach it, and a near `call` to it is refused
(`K816-E0138`) because the mismatch is a stack-depth bug.

```ca65 far
.setcpu "65816"
.code
.a8
.i8
start:
    jsl far_fn
    rts
far_fn:
    rtl
```

```k65 far
func start @a8 @i8 {
    jsl far_fn
}
far func far_fn @a8 @i8 {
}
```

### Macros

A `.macro` is an `inline`. Its body is expanded at each use, which is the
only place K816 can inject a parameter: an immediate alias `#name` or a
bare `name` standing for a variable or address, bound positionally from
the use site's arguments. A register the body expects is a parameter too.
`.local` labels need no declaring: every label of an `inline` is renamed
per expansion.

```ca65 macros
.setcpu "65816"
out  = $0200
out2 = $0201
.macro store where
    sta where
.endmacro
.code
.a8
.i8
start:
    lda #$42
    store out
    lda #$43
    store out2
    rts
```

```k65 macros
var out  = $0200
var out2 = $0201
inline store @a8 (a, where) -> a {
    sta where
}
func start @a8 @i8 {
    lda #$42
    store a, #out -> a
    lda #$43
    store a, #out2 -> a
}
```

### Conditional assembly

```ca65 conditional
.setcpu "65816"
DEBUG = 1
.code
.a8
.i8
start:
.if DEBUG
    lda #1
.else
    lda #2
.endif
    rts
```

```k65 conditional
const DEBUG = 1
func start @a8 @i8 {
#if DEBUG
    lda #1
#else
    lda #2
#endif
}
```

`.ifdef X` is `#if X` over a name defined with `const` or in a `[ … ]`
block; `.error` is `#error MESSAGE`.

### Symbols across files

| ca65                       | K816                                                   |
| -------------------------- | ------------------------------------------------------ |
| `.export X` / `.exportzp`  | nothing: every unit-level definition is exported       |
| `.import X`                | `extern func X` / `extern var X` / `extern const X`    |
| `.importzp X`              | `extern var dp X`, or `extern const X:byte` for a value |
| `.include "x.inc"` (equates, structs) | `import "x.k816"` of a unit holding them    |
| `.include "x.inc"` (code)  | a unit of its own, imported                            |
| `.global`                  | nothing                                                |

`import "file"` names another K816 unit, relative to the importing file,
and a unit sees what it imports directly and nothing further. An `extern`
names a symbol **no K816 unit defines** — one a ca65 module still
provides — and carries exactly what ld65 cannot infer: the address size,
and for a function the widths it expects and leaves. `k816 bind` writes
them (below).

```ca65 vectors
.setcpu "65816"
.code
.a8
.i8
start:
    rts
.segment "VECTORS"
    .word 0, 0, start, 0
```

```k65 vectors
func start @a8 @i8 {
}
data VECTORS {
    segment VECTORS
    word 0 0 start 0
}
```

## The converter

`k816 convert` writes the idiom table out for a whole program:

```sh
k816 convert -I src --out-dir converted --check src/*.asm src/*/*.asm
```

Each file named and every file its `.include`s reach becomes a `.kk`
unit, beside its source or at the same place under `--out-dir`. An `.inc`
that the `.asm` of its stem includes is one unit with it — interface
first, then body — and `.macpack generic` is a `generic.kk` of two
`inline`s, `add` and `sub`, that state no width. `-I` is ca65's include
path, and an `.include` that does not resolve through it is a note rather
than a unit. Nothing that exists is replaced without `--force`, and
`--check` compiles every unit written, as one program.

What it writes is the program's shape in K816's words, so that the build
compares with the original's byte for byte:

- **Routines.** A label after a terminator that something outside the
  routine above it names — or that nothing names at all — starts a
  section: `func` when it ends in `rts`, `far func` in `rtl`, `naked`
  otherwise. A label only that routine's branches reach stays a local
  `.label`; a cheap local is `.name`, and an unnamed label is named for
  what it is (`.loop`, `.next`).
- **Widths.** A header states an axis only where the original relied on
  it: an instruction that reads the flag runs before the routine sets it,
  or the routine calls or tail-jumps to one whose header states that axis.
  A routine that sets its widths first gets no header, and neither does
  one that ends in `rti` — the hardware enters it at the interrupted
  code's widths, which nothing can state, and the converter notes where
  the original assumed otherwise. A `sep`/`rep` and its directive are
  `@a8`; a change the routine undoes before its next label is an
  `@a8 { … }` block.
- **Calls.** A `jsr` to a routine is the bare name, a `jsl` to a far one
  `far NAME`, so a call bridges to the callee's header, and a call made at
  a width that header does not state is a note: it is a `sep`/`rep` the
  original does not have. A call whose stack the callee does not return
  from is kept as written, for the compiler to refuse; a `jmp` is kept as
  written too, and the compiler warns where it arrives at another width
  (`K816-W0125`).
- **Data.** A `.struct` is a layout and a `.struct` at an `.org` a
  pinned one; `.tag` runs and `.res` of a struct's size are tables, and a
  label inside one is its element, `TASKS[1]`. An access whose register is
  wider or narrower than its field takes a view. An `.enum` is one
  `const` list, an equate a `const`, an address equate a pinned `var`.
- **Loops and blocks.** A label a conditional branch at the end of a run
  returns to is `loop { … } while COND`, and a conditional branch over a
  run to a label nothing else names is `COND { … }`, the run's own block.
  Inside a loop, a conditional branch back to its top is `COND repeat`
  and one to the label right after it `COND break`; a label goes when
  nothing else names it. A carry a compare left reads as `<` or `>=` and
  any other as `c?` or `!c?`, and the comment on a branch over a run is
  said at the `}` where the branch lands. A loop closed by `bra` is
  `loop { … } always`, a branch over a run that jumps over a second one is
  `COND { … } else { … }`, and an unconditional jump inside a loop to its
  top or past its end is a bare `repeat` or `break`. Each rewrite is
  compiled beside the labelled form and kept only when the two assemble to
  the same bytes; a label stays wherever no statement says the same thing.
- **Everything else stays where it was.** Segments, the order of
  routines and data, and data in a code segment — moving a buffer out of
  `CODE` is a reader's call, not the converter's.

Every place the conversion could not be faithful is a note, printed as
`FILE:LINE: note:`, and the original line is kept beside it as a comment.
The dialect it reads is the one programs use: `.if`, `.scope`, a
`.repeat` outside a macro, and a directive it does not know are each
reported rather than guessed at.

A converted program differs from the original where K816 decided
something the assembler did not: a `sep`/`rep` the optimizer proved
redundant is gone or narrowed, a branch that reaches a label at another
width than the one written in front of it is switched at the branch
(`register-width-aware-syntax.md`, "A label's entry width"), a call
made at a width its callee does not state is bridged, a store of a
register K816 knows holds zero is an `stz`. A `jmp` the source wrote stays
a `jmp`, so a loop the source closed with one keeps its label: K816's
`always` would be the shorter `bra`.
`tools/k816-compare.py --symbolic`, step 5 of the loop, lists each one.

## The loop

The program stays two languages for as long as the conversion runs, and
that is fine: `cl65` compiles `.asm` and `.k816` alike and ld65 links
the objects. One file at a time:

1. **Build the program as it is**, with debug information, and keep the
   result. A CMake build passes `-g` and `-Wl --dbgfile,F` in its
   compile and link options; by hand it is `cl65 -t none --no-target-lib
   -g -C layout.cfg -Wl --dbgfile,before.dbg -o before.xex *.asm`.

2. **Read what the file assumes.** `tools/ca65-widths.py --calls FILE
   …` prints the widths ca65 assembled each label with, as the
   annotation K816 would want, and the call sites whose widths disagree
   with their target's. Those disagreements are where K816 will bridge,
   or refuse, and are worth reading before writing a single line.

3. **Write the file's interface.** `k816 bind --for src/x.asm
   before.dbg -o src/x.ext.k816` writes an `extern` for every symbol the
   module imports from modules still in ca65, and an `import` for every
   one already in K816. The width hints in its comments come from the
   ca65 source; promote the ones the routine really depends on to
   annotations.

4. **Convert the file**, by hand, importing the interface. Add `.k816`
   to the build in place of the `.asm` — in CMake,
   `set(CMAKE_ASM_SOURCE_FILE_EXTENSIONS s;asm;k65;k816;kk)` is the whole
   change, `kk` being the extension `k816 convert` writes — and build. The `K816-CA65-` diagnostics name each ca65 idiom
   left behind and what to write instead, in the editor as in the build.

5. **Compare.** `tools/k816-compare.py before.dbg after.dbg` lists every
   symbol whose bytes changed, with both sides disassembled and the
   first differing instruction marked. Once a file's layout has moved —
   which converting it does — add `--symbolic`: routines are then matched
   by the labels both builds share, an operand is equal when it names the
   same thing (the same fixed number, or the same symbol plus the same
   offset), a branch is equal when it lands on instructions the alignment
   paired, and each instruction carries the register width it runs at, so
   a routine assembled at another width differs even where its
   instructions read alike. That last case is the one to look for: a width
   the original set in a routine's *body* moved into its *header*, where a
   raw `jsr` does not honour it. A routine that changed only
   because one before it changed size shows as moved operands; a
   `sep`/`rep` the optimizer removed, or one K816 added at a call, shows
   as itself. Each is a sentence for the conversion's notes: what K816
   did differently, and whether it was right.

6. **Record what hurt.** The point of the exercise is the list of places
   the language made the file harder to write than the assembler did,
   and the places the width checker refused something the hardware
   allows. Nothing else produces that list.

Interface units written by `bind` are regenerated after each step —
the set of symbols still provided by ca65 shrinks — so keep them out of
the hand-edited files and `import` them.

## What K816 does not have

Known as of this writing, so that a search ends quickly:

- **No `.scope`.** A `func` scopes its local labels, and that is the
  only scope. A ca65 `.scope` of equates becomes `const`s with longer
  names.
- **No `\xNN` string escape.** Write the byte as a value beside the
  string.
- **No bank-byte operator.** `#X >> 16` folds for a fixed address.
- **An `extern`'s contract is trusted, never verified**, exactly like a
  C prototype for an assembly routine. A wrong one is a wrong byte at
  run time. `bind` therefore writes none and quotes the ca65 directives
  instead.
- **`main`'s exit is nobody's contract.** An entry point no analyzed unit
  calls has no caller to satisfy, so a width restore before its final
  `rts` can be deleted (`doc/design.md` §8). A kernel entry reached by
  `jmp` from a reset handler *is* called in this sense and keeps its exit
  width.
- **`.macpack generic`, `.macpack longbranch`.** `add`/`sub` are two
  instructions, or an `inline` with no width that you declare once; a long
  branch is `brl` or the inverted short branch around a `jmp`, written
  out.
- **Parameters on a `func`.** Registers and memory are what crosses a
  `jsr`; an `inline` is the only construct that takes an alias.
- **A header width is a promise about callers, not an instruction.**
  `func f @a16` makes every `call f` bridge to sixteen bits; it emits
  nothing in `f`. A routine entered by `jsr` from code that does not
  bridge, by an `rti` that starts a task, or by a jump table needs the
  width *in its body* — `@a16` as its first statement — exactly where the
  ca65 original had its `rep`.
- **An `inline` with no width runs at its use site's.** Its body is
  expanded in place, so `inline add (#n) { clc adc #n }` is `adc #$04`
  under `@a8` and `adc #$0004` under `@a16`, and is `K816-E0104` only at a
  use site whose own width is unknown. A width written on the `inline` is a
  contract instead, and every use site is bridged to it.
