# The K65 compatibility manifest

**What this is.** One row per rule of the original K65 compiler's grammar,
plus one row per K816 construct that is not in that grammar. Every row carries
a status, the fixture that proves it, and — where the status is not
`compatible` — the reason.

`doc/k65-compat.md` asks for "its own manifest"; this is it, and it is sub-plan
G's primary artifact. It lives in `doc/` rather than beside the sub-plan
because the suite reads it — `plans/` is not tracked, and a test that depends
on an untracked file fails on a clean checkout — and because what it classifies
is the language, which is `doc/`'s subject. `tests/compat.rs` reads this file: every row's fixture has to
exist, every fixture's row has to be here, and the line ranges have to tile the
grammar with nothing dropped and nothing counted twice.

**The inventory is the grammar, not the documentation.** The rows below walk
`src/compiler.inc` of the original K65 checkout — 515 lines, the whole
language — because the original's documentation is partial (`doc/k65/syntax.md`
never mentions `evalfunc`, `bank` gets one line, the illegal-opcode forms
appear nowhere) and its grammar is complete by construction. A row per rule is
checkable; a row per documented feature is not. The `Lines` column is that
file's line numbers, so the walk can be re-checked against it.

**The ruling every row is decided by** (`plans/06-compatibility.md` decision
0): K816 is backwards compatible with K65 wherever compatibility is cheap for
K816; where it is not, K816 recognises the K65 syntax as a named node and
errors out with a specific diagnostic — never a generic parse error, and never
a K65 spelling given a K816 meaning except the one recorded exception
(decision 11). "Cheap" is an implementation judgment made per row; it is the
`Cheap` column below, and the `Reason` column argues it.

## The statuses

| Status | Meaning |
| --- | --- |
| `compatible` | Implemented with the original's semantics; the oracle and K816 agree at the bytes, or at the instruction sequence where layout differs. |
| `intentionally-changed` | K816 does something else on purpose, the difference is documented, and `--strict-k65` reports it. |
| `legacy-defective` | The original (or the legacy K816) did something its own documentation contradicts; K816 does what the documentation says, and the row says what the old behaviour was. |
| `backend-different` | Same behaviour, different bytes or layout, because ca65/ld65 own encoding and placement. Compared at the instruction sequence. |
| `K816-extension` | Not in the original grammar. `--strict-k65` rejects it. |
| `open` | No decision yet. The task named in the reason settles it. No row reads this; G10 closed the last four, and the status stays defined so that a rule a later sub-plan adds has somewhere to sit before it is decided. |

`reserved` is deliberately absent: a row that is still reserved is a row with
no decision, and `open` says the same thing while naming who closes it.

## The `Cheap` column

Decision 0 rules that K816 is backwards compatible with K65 **wherever
compatibility is cheap for K816**, and that the judgment is made per rule. This
column is that judgment, written down so it can be read rather than inferred
from the `Reason` prose. It is on the grammar table only: the second table
holds constructs K65 does not have, and there is nothing there to be compatible
with.

| Cheap | Meaning |
| --- | --- |
| `yes` | Compatibility here was cheap and K816 has it: a grammar alias, a lowering the existing machinery already had, or an interpreter feature the existing interpreter already had. It says nothing about the *bytes* — a `yes` row may still be `backend-different`, and a `legacy-defective` row is usually `yes` because what K816 implements is the rule the original's own grammar promises. |
| `no` | Compatibility would cost a decoder, a second linker, section mutation, or a semantics the 65816 cannot realize. The `Status` says what K816 does instead, and decision 0 requires it to be a named node with a diagnostic rather than a parse error. |
| `n-a` | The rule has no live production to be compatible with — commented out in `compiler.inc`, or referenced by no other rule. Exactly the rows whose `Fixture` reads `n/a`, and for the same reason. |

A row that reads `yes` and is **not** `compatible` is a change K816 chose
without having to, and its `Reason` has to say why. There are five, and they
are decision 0's recorded exceptions rather than a category: `topelem-eval-block`,
`topelem-const`, `instr-stack-flags`, `flag-tokens` and `number-eval-bracket`.
A row that reads `no` is never `compatible`, and `tests/compat.rs` asserts it.

## The `Strict` column

What `--strict-k65` does where the row's construct appears (decision 20). It is
a stated fact per row rather than something derived from `Status`, because
`Status` does not carry the one thing the flag needs to know — whether the
construct *compiles*. Fifteen of the eighteen `intentionally-changed` grammar
rows are already hard errors in K816, and warning at them again would say
nothing; three more name a corner (an out-of-range wrap, `index(t, -1)`) that
no node marks, and warning at every `#if`, every bracket and every subscript
would drown the flag in a program that never touches the corner.

| Strict | Meaning |
| --- | --- |
| `rejects` | An error, one per occurrence: the construct is a K816 extension with no K65 spelling. Only a `K816-extension` row reads this. |
| `warns` | A warning, one per occurrence: the construct compiles under both compilers and means something else here. Only an `intentionally-changed` row reads this. |
| `—` | Nothing to report, and the `Reason` says which of the three it is: the compiler already refuses the construct, so the flag has nothing to add (decision 0); the row is about behaviour rather than about anything a source can contain; or there is no difference to report. |

`compat::classify` mirrors this column, and `tests/compat.rs` reads the file
and checks that the set of rows the flag reports over the corpus is the set the
column marks.

## Status of the walk

Written in G0 on 2026-08-21, completed in G10. Where the `Reason` column reads
that something was "measured", the evidence is
an oracle golden under `tests/compat/k65/`, produced by the original K65
compiler at the revision `tests/compat/oracle.lock` pins.
Fixtures under `tests/compat/` are named without that prefix; a fixture under
`tests/golden/` is named with its `golden/` one. Every row names one, and
`tests/compat.rs` checks that it exists, that it contains the construct the row
claims, and that no row is left `open`. The two exceptions read `n/a` rather
than a path: `topelem-macro` and `putlabel` classify grammar lines that carry
no live production, so no source can contain them, and their `Cheap` cells say
the same thing in the same words.
