Since G6 the whole file compiles, and the golden is what the oracle answered:
`1E 14 28 04` for the four spellings, `01 02 03` against `01 03 05 07` for the
transform, `43 41 42` for the string, `01 00 01` for the comparisons.  Every

Two differences in the *image*, both the linker's: the original opens with a
`JMP main` stub K816 does not emit, and it drops `source` because nothing
references it, where ld65 keeps a section that is in the link.  So K816's
image carries `0A 14 1E 28` where the original's carries the stub.

`source.size` is why a method call is desugared in the *interpreter* rather
than reported by the walk analysis does over reserved calls: `size(x)` was a
`reserved_eval_call` node and `x.size` was not, so the second spelling came
out as an undeclared name until G4 made the two spellings one complaint.  G6
finished the job by taking `size` out of the reserved family in the grammar
too, which is what lets both spellings reach one implementation.

Before G6 there were six `K816-E0201` and one `K816-K65-0002`: three
`evaluator [ ]` entries, three section reads, and the refusal.
Before G4 there were eleven `K816-E0201`, one per construct the grammar named
and no task had given a meaning.  Before G1 there were fourteen, three of them
`K816-E0101` for undeclared names plus one `K816-E0001` - the shape of a file
whose `evaluator`, `pi` and method-call syntax arrived as something else.

**A method call is spelling; a string cannot reach a byte; `evaluator [ ]` is a
transform over generated bytes.**  Three of decision 5's open questions, in one
golden:

    1E 14 28 04    index(source,2), source[1], source.index(3), source.size
    01 02 03       filtered_literals   - the transform did NOT run
    01 03 05 07    filtered_generated  - the transform DID run
    43 41 42       filtered_string     - and it runs per character
    01 00 01       "ab"=="ab", "ab"=="ba", "a"<"b"

  - **Method calls are sugar.**  `EvElem . AllIdent ( args )` compiles to
    `name(EvElem, args...)` and `EvElem . AllIdent` to `name(EvElem)`
    (`compiler.inc:448-449`), so `source.index(3)` *is* `index(source, 3)` and
    `source.size` *is* `size(source)`.  There is no method table and no object
    model.  Decision 5's refusal is lifted: this is a grammar rule, which
    decision 0 calls cheap, and G1 and G4 land it.

  - **What `[ ]` indexes is a section.**  `Eval_Index_1D`
    (`compiler_eval.cpp:340`) takes the section a data label names, builds its
    raw bytes, and returns the byte at the index - or zero, out of range, with
    no diagnostic.  There is no array value in the original evaluator, so
    `arr = [10, 20, 30]` is not an array literal: the comma is the evaluator's
    *pop* operator and the bracket is `30`.

  - **`evaluator [ code ]` is a per-byte transform, and it reaches only
    generated bytes.**  `Data -> evaluator [ EvalCode ]` precompiles a program
    into the section's own evaluator (`compiler.inc:93`); `datavalue` and
    `datastr` then bind `x` to each byte, run it, and mask the result to eight
    bits (`compiler_src.cpp:466-500`).  Both are reached by `for ... eval`
    values, by string characters through `charset`, by every byte of a
    `binary`, and by every byte of an image tile - and *not* by a literal data
    entry, which takes the `oparith(".byte", ...)` path instead
    (`compiler.inc:62`).  The golden's `01 02 03` against `01 03 05 07` is
    that distinction and is the reason this fixture keeps the two cases in
    separate sections.

    Note also that this masking is `int(v) & 0xFF` - a *truncation*, where
    every other integer boundary rounds.  G6 implements the transform; the two
    conversions are not the same function and must not be merged.

  - **String values exist, and stop at the evaluator's edge.**  `==`, `<` and
    `+` work on them (`compiler_evany.h`), `print` and `error` take them, and
    the golden's `01 00 01` is three comparisons.  A string that reaches an
    integer boundary is an error - `"a" + "b"` in a data entry ends the build -
    because `Eval_Exec` calls `ToNumber` on the result.  So strings are a
    value *inside* an evaluation, never a value *of* one, and that is the whole
    feature.
