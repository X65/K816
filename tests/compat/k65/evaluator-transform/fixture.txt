**The section transform is positional, replaced rather than composed, masked
by truncation, and it reaches a `binary`.**  Four things `eval-forms` did not
ask, in one golden:

    01 02              written above the transform: untouched
    64 C8 2C           `x * 100` over 1, 2, 3 — and 300 masked to $2C
    02 03              a second `evaluator` replaces the first
    FF FE              `0 - x` masks a negative the same way
    01 02              `x + 0.6` truncates rather than rounding
    11 12 13 14        every byte of the `binary`
    64 0B 11           index(filtered, 2), size(filtered), index(included, 0)

The masking is `int(v) & 0xFF` (`compiler_src.cpp:466`), and the `int` is
`EvalAny::ToInt` — so `x + 0.6` over 1 is 1, where the evaluator's boundary
rule would have made it 2, and `0 - 1` is `$FF`.  **The two conversions are
not the same function.**  `k65/eval-integer-boundary` pins the rounding one;
this pins the truncating one; `postmortem.md` §G.2.2 is where G0 warned that
merging them would miscompile.

Replacement rather than composition follows from where the program lives: the
transform is precompiled into the *section*, and a second `evaluator` entry
overwrites it.  So does the positional rule — the bytes above the entry are
already emitted, and nothing goes back for them.

`index` and `size` read the section **after** the transform: `index(filtered,
2)` is `$64`, the transformed byte, not the 1 the loop generated.  That is
what settles where K816 has to apply it — in the walk that produces a
section's bytes, not at emission — because analysis records those bytes for
the read to find.

Reaching a `binary` is the reason K816 reads an included file at all.
Decision 8 maps the construct to `.incbin` and rejected emitting `.byte`
lines; a transform K816 does not apply would be a wrong image, so the file is
read exactly where its bytes are needed — a section with a transform, or a
section something indexes — and `.incbin` covers everything else.

**`assigning` is the shape `--strict-k65` warns about**, added after G10b's
review found that this row was marked `warns` and its own fixture never made
the flag say so - the only witness in the corpus was a legacy fixture the row
does not cite.  `evaluator [ T = x, T ]` transforms every byte to itself, so
the bytes are `07` in both compilers and the warning has something to point at.

**What the assignment does afterwards is the divergence, and it cannot be
committed as a source.**  Probed with the oracle rather than left as reasoning:
`[ SEEN = 0 ]` above `evaluator [ SEEN = x ]`, with `[ SEEN ]` read two entries
later, gives **7** in the original - the transform's write survives it.  K816
refuses that source twice over, and both refusals are its own rules rather than
this one: `EVAL_REASSIGNED` (`K816-E0149`) for a name assigned in two blocks,
and `K816-E0101` without the priming assignment, because the transform's copy
of the environment does not outlive the byte.  So the row states the divergence
and this file measures the half a committed source can hold.
