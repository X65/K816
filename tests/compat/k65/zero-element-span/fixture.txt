**`var X[0]` declares a name and reserves nothing, in both compilers.**

The oracle golden is `A5 00` - `next`, the first allocated name after the
bracket, at `$00`.  So `z0[0]` took no bytes and the allocator carried
straight on.  Nothing in the original checks the count: `BracketNumber ->
[ EvalCode ]` (`compiler.inc:330`) is the evaluator, and zero is a value like
any other there.

K816 emits `.res $00` and reserves nothing either, so the name exists and
holds nothing.  Only the address differs, and for the reason every allocated
variable's does: ld65 places it.

**This was a narrowing until G3 was reviewed.**  K816 reported `K816-E0141`
here, from sub-plan E's rule that an element count must be at least one - a
rule written for `var X:byte * N`, where a zero count names storage something
is about to index, and which the raw span shared only by sharing the code.
The two forms are not the same question: `* N` has no K65 spelling and keeps
the rule, and `var X[0]` is a K65 declaration the original accepts, which
decision 0 says to keep working wherever that is cheap.  It was one condition.

`var X:byte * 0` and a field's `[0]` still report `K816-E0141`, and
`array-declarations` beside this is where a *non-zero* bracket is measured.
