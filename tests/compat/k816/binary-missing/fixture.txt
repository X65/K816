**A missing `binary` is a K816 diagnostic with a span.**  The original calls
`Error("Can't open file: …")`, whose error path unwinds through a bad free and
takes the compiler with it; ca65 would report the name without a line.  K816
checks the file exists before either of them gets the chance, which is the
half of decision 8 that is K816's own.

The caret is the *string*, not the line: the complaint is about the path.  The
note names the resolved path K816 looked at, because "not found" without
"where I looked" is the half of the message that costs a debugging session,
and the help names `--bin-include-dir` — ca65 resolves the same name against
its own search list, so a build that assembles somewhere else needs it and
K816 cannot check that for anyone.
