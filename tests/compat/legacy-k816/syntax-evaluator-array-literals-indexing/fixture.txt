`arr = [10, 20, 30]` followed by `arr[1]`.

The legacy K816 read this as an array literal.  The original has no array
literal: `Number -> [ EvalCode ]` and `EvalCode`'s comma is the *pop* operator
(`compiler.inc:328,359-360`, opcode 1), so `[10, 20, 30]` is 30, and the value
`arr[i]` indexes has to be a section.  A row where importing the legacy
fixture as truth would have enshrined a construct K65 never had, which is what
decision 2 is for.

Today, after G1: three `K816-E0001` and four `K816-E0201`.  Before G1 it was
one and three.  The construct that fails is the same one - `[` cannot open a
value inside an evaluator expression, because there is no array literal to
open - but a bracket now holds a *statement list*, so recovery from the stray
`[` ends the enclosing block at the literal's `]` and the two entries after it
are re-parented at the file root instead of being swallowed by one error node.
More diagnostics over the same defect, all of them pointing at source the
original also refuses.  `arr[1]` and `index(arr, 2)` themselves still parse -
