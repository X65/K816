`index` and the `[ ]` indexing operator.

The oracle answer that matters is in `tests/compat/k65/eval-forms/`: what is
indexed is a **section** - a data label - not an array value, and `tab[i]` is
exactly `index(tab, i)`.  G6 implements it, and the whole file compiles.

The golden is what the reads answered.  `arr` is `0A 14 1E`; `A` is
`(1 ?< 2) ?> 3`, which is 3, so `a=[A]` is `A9 03`; `B` is `arr[1]`, so
`x=[B]` is `A2 14`; `C` is `arr[2]`, so `y=[C]` is `A0 1E`.  A read is an
immediate in operand position, which is `number`'s row.

The file is also where the *reach* of a refusal used to show.  Until G6 the
first read stopped the block, `A` survived because it was assigned above it,
and `B` and `C` came out `K816-E0101` - an evaluation stops at its first
unanswerable question and keeps everything it had already decided.  That shape
is still the original's and still K816's; there is simply nothing unanswerable
in this file any more.

Before G4: four `K816-E0201`, one per bracket.  After G4: one, at `arr[1]`,
with the two `K816-E0101` behind it.
